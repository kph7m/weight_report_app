# AIコメント生成機能

## 概要

体重入力後にOpenAI Responses APIを利用してコメントを生成する。

生成したコメントはレポート画面へ表示し、アプリ内DBへ保存する。

---

# API

## 使用API

Responses API

`previous_response_id`は使用しない。

毎回独立したリクエストとして実行する。

## タイムアウト

- Responses APIのタイムアウトは30秒とする。
- 30秒以内にレスポンスを受信できない場合はAPI失敗として扱う。

## 使用モデル

- Responses APIで利用するモデル名はリクエスト処理内にハードコードしない。
- モデル名は定数として一元管理し、今後のモデル変更時に修正箇所が複数に分散しない構成とする。

---

# API送信データ

## プロフィール

- 身長
- 目標体重

## 今日のデータ

- 今日の体重
- 前日比
- 目標体重までの残り

## 直近7日間

- 日付
- 体重

## 直近7日平均

- 日付
- 7日平均

## 前回コメント

前日に生成したコメント。

初回は空文字とする。

---

# システムプロンプト

```text
あなたはダイエットアドバイザーです。

以下のルールでコメントを生成してください。

・親しみやすく、少しお嬢様口調の優しい話し方
・前向きに励ます
・300文字以内
・数値の変化を必ずコメントする
・直近7日間の傾向を考慮する
・前回コメントの表現を繰り返さないでください。
同じ褒め方や言い回しを避け、
できるだけ異なる観点からコメントしてください。
・絵文字は使用しない
・Markdownは使用しない
・文章のみ返答する
```

## プロンプト管理

- システムプロンプトはソースコードへ直接記述しない。
- `assets/prompts/ai_comment.txt`として管理する。
- Serviceがアセットから読み込んでResponses APIのリクエストに使用する。

# ホーム画面

体重入力確定後、`character_thinking.png`を表示する。

入力UIは操作不可とする。

---

# API待機

Responses APIの返却待ち中は`character_thinking.png`を表示し続ける。

---

# API成功

API返却後、すぐにレポート画面へ遷移する。

現在実装されている3秒待機処理は削除する。

## AIコメントのバリデーション

レスポンスから取得したAIコメントが以下のいずれかに該当する場合は、API失敗として扱う。

- `null`
- 空文字
- 空白文字のみ

バリデーションに失敗したコメントは表示・DB保存しない。

## 300文字制限

- 取得したAIコメントが300文字を超える場合は、アプリ側で300文字に切り詰める。
- レポート画面へは切り詰め後のコメントを表示する。
- DBへは切り詰め後のコメントを保存する。

---

# レポート画面

APIから返却されたコメントを左下コメント欄へ表示する。

現在表示している固定コメントは削除する。

---

# DB

OpenAIから返却されたコメントを保存する。

## 保存項目

- 日付
- 体重
- AIコメント

翌日は前日のAIコメントを取得してAPIへ送信する。

---

# エラー

API失敗時は「今日はコメントを生成できませんでした。」を表示する。

DBには保存しない。

API失敗時は、上記メッセージに加えてエラーログをダイアログ表示する。

エラーログには、原因の特定に必要な範囲で以下を含める。

- HTTPステータスコード
- Responses APIが返したエラーレスポンス
- タイムアウトやレスポンス解析失敗の詳細
- アプリ内の発生箇所

APIキーなどの秘密情報はエラーログに含めない。

以下の場合をAPI失敗に含める。

- HTTP通信エラー
- Responses APIがエラーレスポンスを返した場合
- 30秒のタイムアウト
- AIコメントのバリデーション失敗

# 実装方針

既存のRepositoryパターンとRiverpodによる状態管理を維持する。

AIコメントは日次の体重記録に属するデータとして扱い、既存の`WeightEntry`にnullableなAIコメントを追加する。日付と体重を持つ別の保存Modelは新設しない。

既存構成に合わせ、AIコメント生成機能を以下の責務に分離する。

## Model

- `WeightEntry`にAIコメントのnullableフィールドを追加する。
- Responses APIへ送信するデータは、UIやDBのModelに依存しないリクエストModelとして定義する。

## Repository

- 新しいRepositoryは作成せず、既存の`WeightRepository`を拡張する。
- AIコメントのアプリ内DBへの保存を担当する。
- 前日に生成されたAIコメントの取得を担当する。
- OpenAI Responses APIへの通信は行わない。

## Service

- OpenAI Responses APIへのリクエスト送信とレスポンス解析を担当するServiceを追加する。
- `previous_response_id`を使用せず、毎回独立したリクエストを送信する。
- 30秒のタイムアウトを適用する。
- モデル名は一元管理された定数から取得する。
- システムプロンプトは`assets/prompts/ai_comment.txt`から読み込む。
- AIコメントのnull・空文字・空白文字のバリデーションと300文字への切り詰めを担当する。
- アプリ内DBを直接操作しない。

## Provider

- RepositoryとServiceを画面から利用できるように提供する。
- AIコメントの生成中・成功・失敗の状態を管理する。
- API送信データの組み立て、Serviceの呼び出し、成功時のRepositoryへの保存を調停する。
- Serviceがタイムアウトまたはバリデーション失敗を返した場合は、Repositoryの保存処理を呼び出さない。

## Screen

- ScreenからOpenAI Responses APIおよびIsarを直接操作しない。
- Providerの状態を監視し、生成中の入力UI無効化、考え中表示、成功時の画面遷移、失敗時のメッセージ表示のみを担当する。

既存コードの可読性・保守性・テスト容易性を優先して実装する。
